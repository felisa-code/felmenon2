不要上傳 ZIP 本身，也不要把整個 felmenon2 資料夾再多包一層。根目錄必須直接看到 index.html。GitHub 網頁每次最多 100 檔，本包已控制在範圍內；若介面限制，可先分批上傳素材，最後上傳 .github。

.github/workflows/ 內應有四份 yml。若拖曳未包含該目錄，用 Add file → Create new file，輸入完整路徑，照包內同名檔逐一貼上並 Commit。

4確認案例文案，無需 API 金鑰

本版 9 張精選案例已包含標題、介紹與 ALT，並設為人工定稿，直接上傳即可。不需要建立 OPENAI_API_KEY，也不需要額外 AI API 費用。

新照片傳給 GPT→提供公開 felmenon2 Repo 網址→取得新版 cases.json→上傳照片與資料檔

案例照片放 cases/；文案資料檔放 data/cases.json。手機一次顯示 1 張大圖，可左右滑動、按箭頭或縮圖選圖，並有頁碼；標題與單行簡介位於照片下方。點開顯示原圖與完整介紹，不自動切換。首頁程式不用修改。

未設定 API 金鑰時，網站不會自動看圖寫文案；若只上傳照片，會先使用通用備援文字。補上 GPT 提供的資料檔後即可顯示正式文案。PDF 的自動轉圖與更新不依賴 AI 金鑰。

6以後只需要兩種上傳

新增案例照片替換電子型錄
Code → cases → Add file → Upload files。選 JPG／PNG／WebP，以不同檔名新增，例如 office-20261101.jpg。Code → 回到 Repo 根目錄 → Add file → Upload files，上傳同名 catalog.pdf，確認取代後 Commit。
Actions：Update case photos。成功後自動產生 title、description、alt 與新案例卡片。Actions：Update PDF catalog。成功後更新分頁圖片、頁數與 PDF 下載，免改首頁。

完全相同圖片不重複展示；HEIC 請轉 JPG。網頁上傳單檔不得超過 25 MiB，較大 PDF 請先壓縮成網站版。

目前型錄是 30 個 PDF 跨頁，網站拆為 60 書頁；手機看單頁、電腦看雙頁，完整 PDF 內容不變。

7人工定稿與故障處理

要改文案：data/cases.json → 鉛筆編輯那張的 title、description、alt，並設 locked: true、manual: true、status: "ready"，Commit 後保留定稿。

補做失敗照片：Actions → Update case photos → Run workflow，regenerate 留空；重新生成一張則填相對 cases 的精確檔名，該操作會覆寫該張人工文案。

狀況下一步
網站 404確認 Pages 選 GitHub Actions、deploy 成功、網址含 /felmenon2/。
照片有了但沒有 AI 文案看 Actions Summary，檢查金鑰與額度，修正後手動 Run workflow。
更換 PDF 後仍顯示舊版可能轉換失敗，正在保留最後成功的圖與下載。確認來源 PDF 可開啟，再重新上傳。
空白首頁或 2 Bytes 檔案核對根目錄 index.html，不能有檔名空白或括號編號；重新上傳正確檔案。
git push rejected／403先重跑；若持續失敗，確認新 Repo 的分支保護與組織政策允許 bot 提交 main。不要強制推送。

回復照片或型錄：重新上傳上一份正常來源檔。回復文案：data/cases.json → History 取回該筆文字並 Commit。詳見 README.md。
